Ticket tracker PWA — plan (2026-11-24)

Goal
Turn Downloads/ticket-tracker-v2.html (single-file tracker, built as a claude.ai artifact) into an
installable phone app. Keep the design and every feature. Load data from ledger-fixed.json. Sync with Supabase.

Steps
1. index.html = the original page, design untouched. Replace the artifact-only APIs:
   - claude.use("db"/"user") sync  -> Supabase (email+password auth, one row per user in table `ledgers`,
     whole ledger as jsonb + rev timestamp, last write wins, realtime subscription + re-pull on app focus).
   - claude.use("downloads") export -> Blob download.
   - localStorage stays as the offline copy; unsynced edits are pushed when back online.
2. Data: ledger.json (copy of ledger-fixed.json) seeds the app on a device with no local data.
   Remote data newer than the seed wins. Also add Import/Export JSON backup buttons.
   ledger.json is gitignored: it is private financial data and must not land on public GitHub Pages.
3. PWA: manifest.webmanifest, sw.js (offline app shell, Supabase calls never cached), icons
   (PNG generated by tools/make-icons.js, zero deps), iOS meta tags.
4. config.js holds the Supabase URL + anon/publishable key (safe to publish; RLS protects the data).
5. supabase/schema.sql: table, RLS policies (own row only), realtime publication.
6. README with setup: create free Supabase project, run SQL, fill config.js, deploy to GitHub Pages
   (HTTPS needed for install), sign in on PC first so ledger.json gets uploaded, then on the phone.
7. Verify: script syntax check, load in Chrome locally, check seeding + render + no console errors.

Tickets header: Sync / Review / Export / Import (2026-11-25, from "inventorypage.jpg"):
User choices: mailbox = Gmail; find emails by KEYWORD search (not per-platform parsers);
server = Supabase (not Cloudflare). Zero cost.
- Header buttons: [Sync v] [Review (n)] [Export v] [Import] [+ Add New].
  Export menu: Backup JSON, Tickets CSV, Pulling CSV, Monthly P&L CSV (same code as Data page).
  Import: CSV or JSON file (same code as Data page). Sync menu: "Sync ticket emails" (Gmail via
  IMAP) and "Search keywords" (edit the list), plus "last synced".
- Server: Supabase Edge Function supabase/functions/mail-sync/index.ts (no imports, one file).
  * Only the owner may call it: checks the caller's Supabase login against secret OWNER_EMAIL.
  * Gmail login with an app password from secrets GMAIL_USER / GMAIL_APP_PASSWORD (never in the repo
    or the browser). Read-only: EXAMINE the "All Mail" folder (found via LIST \All, else INBOX).
  * Search: X-GM-RAW  subject:("kw1" OR "kw2" ...) -category:promotions  + after:<date> (first sync
    looks back 120 days), newest 30 messages, first 60 KB of each.
  * Parses MIME (multipart, base64, quoted-printable, charsets, encoded subjects) and GUESSES:
    type purchase/sale, event (cleaned subject), event date, qty, total + price each, currency,
    sector / row / seats. Returns them; it never changes the ledger itself.
- App: results go into S.mail (pending review); handled ones go into S.seen (message ids) so they
  don't come back. Both are saved and synced with the ledger and kept in backups.
- Review overlay: one card per found email (subject, sender, date, snippet) with the guesses as
  editable fields. "New tickets" -> creates a ticket group; "Sale" -> pick the group (best name
  match preselected), adds a sale; "Ignore" -> hides it. Non-EUR amounts: CZK converted at the
  app's 24.32 rate, other currencies left for the user to fix (flagged).
- Tests: node --test (Node 24 runs the .ts directly) for MIME decoding, the guesses, and the IMAP
  reader against a scripted fake Gmail conversation. Real Gmail can only be tested once the user
  has set up Supabase + the app password.
- User steps (README): Supabase project + schema + config.js, sign in, Gmail 2-step + app password,
  create the Edge Function in the dashboard editor, add the 3 secrets.

Email reader tuning v2 (2026-11-27), from the first real sync of 30 emails:
- Noise dropped: query excludes helpdesk / "on sale" / presale / welcome / newsletter subjects, and the
  parser marks such subjects "skip" (never returned).
- New type "transfer" (transferred / accepted / delat biljetter / in your account …). Review card
  "Transfer" picks the group and sets it to Transferred or Pending transfer.
- Forwarded / Re: copies merged (same base subject, within 4 days, no conflicting totals): the original
  wins, empty fields filled from copies, copies' ids in `alt` so Add/Ignore marks all of them seen.
- Forward header block stripped before guessing; event date must be after the email's own day.
- Event names: order numbers and shop words removed; body fallback ("Booking confirmation for X at …",
  "tickets for X").
- Fetch limit 60 KB -> 150 KB per message. Function returns cleaned `text` (3000 chars) for tuning;
  the app keeps it in memory only (window.__mailText), never saved.
- Tests: 16 pass (6 new from real subjects). sw.js tt-v29. User must re-paste the function.
- Browser tab icon (favicon) is now the round Ō mark (icons/mark.png) instead of the OŌS app icon;
