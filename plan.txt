Ticket tracker PWA — plan (2026-11-24)

Goal
Turn Downloads/ticket-tracker-v2.html (single-file tracker, built as a claude.ai artifact) into an
installable phone app. Keep the design and every feature. Load data from ledger-fixed.json. Sync with Supabase.

Steps
1. index.html = the original page, design untouched. Replace the artifact-only APIs:
   - claude.use("db"/"user") sync  -> Supabase (email+password auth, one row per user in table `ledgers`,
     whole ledger as jsonb + rev timestamp, last write wins, realtime subscription + re-pull on app focus).
   - claude.use("downloads") export -> Blob download.
   - localStorage stays as the offline copy; unsynced edits are pushed when back online.
2. Data: ledger.json (copy of ledger-fixed.json) seeds the app on a device with no local data.
   Remote data newer than the seed wins. Also add Import/Export JSON backup buttons.
   ledger.json is gitignored: it is private financial data and must not land on public GitHub Pages.
3. PWA: manifest.webmanifest, sw.js (offline app shell, Supabase calls never cached), icons
   (PNG generated by tools/make-icons.js, zero deps), iOS meta tags.
4. config.js holds the Supabase URL + anon/publishable key (safe to publish; RLS protects the data).
5. supabase/schema.sql: table, RLS policies (own row only), realtime publication.
6. README with setup: create free Supabase project, run SQL, fill config.js, deploy to GitHub Pages
   (HTTPS needed for install), sign in on PC first so ledger.json gets uploaded, then on the phone.
7. Verify: script syntax check, load in Chrome locally, check seeding + render + no console errors.

Design pass (2026-11-24, from user's reference screenshot of a dark dashboard)
- Whole app restyled: near-black bg with faint pink glow top-right, flat #141415 cards, 22px radius,
  thin coloured accent line on top of stat cards, uppercase letter-spaced labels, big tight numbers,
  pink #ff2e88 accent, Inter font. Status line becomes the eyebrow ("● SYNCED TO YOUR ACCOUNT").
- Profit chart is the first thing on screen (above the tabs): big combined-profit number + "last sale"
  on the right, range 7 days / Month / All, optional running total, month nav.
- Three smooth (monotone cubic) lines: Tickets pink (filled area), Pulling white, Combined blue #4d8dff (changed from grey at user's request).
  Faint grid, grey axis labels, tap/hover shows ringed dots + dark tooltip with coloured squares.
- Below the chart: 4 stat cards (ticket profit, pulling profit, tickets sold, unsold at cost).
- Monthly P&L tab removed at the user's request (2026-11-24). Only Tickets and Pulling tabs remain;
  the "Export monthly P&L CSV" button in Data stays unless the user says otherwise.
- Graph switch above the chart: All lines (the 3 together) | Tickets | Pulling | Combined. A single
  graph gets its own scale, the filled-area style, a 1-row tooltip, and the big number/subtitle show
  that graph's total. The choice is remembered on the device. On PC both switches share one row.
- Recap (Tickets > ticket > View recap), from user's 3rd reference: "ARTIST RECAP" label above a
  purple gradient ticket card with glowing top edge; ADMIT ONE · RECAP + № code; gradient avatar;
  heavy title (Inter 900); "— NET PROFIT —"; huge green number with € superscript over faint purple
  wave lines (seeded from the code); ≈ Kč; Bought for / Sold for columns; Tickets sold x / y + status;
  green ticket-shaped boxes with side notches; dashed tear line with side notches; purple ROI footer
  with barcode + code; "Issued <date>" below. Solid near-black backdrop so the notches read as cut-outs.
  Follow-up: recolored from purple to the app's pink-red (profit stays green); the ticket scales to
  fit the screen height (no scrolling, re-fits on resize); waves flow continuously (phase animated
  per frame, stops when the recap closes, still for reduced-motion users).
- Side menu (from user's 2nd reference): sticky top bar (☰ button, current section title, app icon) +
  slide-in drawer from the left over a dimmed, blurred page. Header (icon, "Ticket tracker", v3),
  groups OVERVIEW: Dashboard / SALES: Tickets, Pulling / SYSTEM: Data & export, Sync. Active item
  pink-tinted with pink bar on the left. Footer card: ticket groups, sold/unsold, pink progress bar.
  Closes on backdrop tap, item tap, Esc, or swipe left.
- Separate pages (user: "I don't want everything to be on the same page"): Dashboard (chart + stat
  cards, opens by default), Tickets, Pulling, Data & export, Sync. One view shown at a time, address
  #tickets / #pulling / #data / #sync so the phone's back gesture works. Tab row removed (the menu
  replaces it). Messages (e.g. invalid sale) show as a toast at the bottom on any page.
- Desktop (>=1024px): full width with 12px margins on every page. Dashboard is locked to one screen
  height (no scrolling): compact title row, chart card filling the left, 4 smaller stat cards stacked in one column on the right (~21% width).
  The chart draws at its box's real pixel size (redrawn on window resize). Phone layout unchanged.
- Service worker: page requests go network-first so design updates show on the next load.
